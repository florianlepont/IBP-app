<objective>
Establish the classification target — the CNPF Factor A genus list — and assemble a licence-clean
image corpus for it, with per-genus sample counts and licence provenance recorded as they are
found.

Purpose: RESEARCH.md's central negative finding is that no pretrained, licence-clean, CNPF-genus
classifier exists anywhere it looked. The corpus is therefore the spike's real bottleneck, and its
per-genus coverage sets a hard ceiling on the partial-go set (D-04) before any model is trained.
RESEARCH.md also records that the genus list itself was never transcribed into this repository —
the Wave 0 gap list names it explicitly — so this plan produces it.

Output: a 34-class label set, a licence-filtered corpus with stratified splits, and sections 2 and
3 of the measurement document filled with real counts and real licence citations.

Timebox discipline (D-19): this plan and plan 04 together are the bulk of the two-to-three day
budget. If the corpus cannot be assembled, that is the answer — see the early-exit criterion in
task 3. A well-evidenced no-go is a successful outcome for this phase.
</objective>

  <files>spike/species-recognition/train/prepare_dataset.py, spike/species-recognition/data/raw/, spike/species-recognition/data/splits/, docs/technical/species-recognition-spike-measurements-v1.md</files>
  <action>
    Install the approved package set into the spike venv, then build the corpus.

    Licence constraint first, because it is disqualifying rather than merely inconvenient. D-09
    requires a permissive, redistributable licence for the model and, explicitly, for any dataset
    used. RESEARCH.md Pitfall 1 is the failure mode to avoid: a model or dataset whose own badge
    reads open while its underlying photographs carry a non-commercial restriction, which is
    incompatible with a public store listing even for a non-profit that takes donations. Trace every
    image source back to the licence on the photographs themselves, not to the licence on the
    repository or the model card.

    Candidate sources, in the order RESEARCH.md recommends. Pl@ntNet-300K, recorded as CC-BY on
    Zenodo — but re-verify the licence text on the record itself rather than trusting RESEARCH.md's
    second-hand note, which its own assumption A4 marks as a strong signal and not a legal
    guarantee. GBIF occurrence media, filtered to CC0 and CC-BY records only. Exclude anything
    carrying a non-commercial term. RESEARCH.md records iNaturalist's licence structure as mixed,
    with a commercial-AI-training prohibition — treat its CC-BY-NC portion as unusable and take only
    what is unambiguously CC0 or CC-BY, or skip it entirely if separating the two is not fast.

    Aggregation to genus. Source datasets label at species level. RESEARCH.md Pitfall 2 names the
    trap: reusing a species-level figure as a genus-level one invalidates the go/no-go. Aggregate
    species labels up to genus in `prepare_dataset.py` before anything is counted or split, mapping
    each source species to one of the 34 classes in `genus_labels.txt` and discarding species that
    map to none. Handle the two Quercus classes explicitly — deciduous and evergreen oaks are
    separate classes and a species that maps to Quercus must be resolved to the right one or
    dropped with a recorded count, never assigned arbitrarily.

    Single subject only. D-10 as amended on 2026-09-22 scopes this phase to single-subject
    photographs: one tree, one bark close-up, one leaf close-up. Keep the corpus to single-subject
    images. Do not gather, prepare or split any multi-tree or stand imagery, and do not implement
    any detection step — the stand case is not measured in this phase, and RESEARCH.md Pitfall 3
    records what happens when a whole-image classifier is pointed at a stand photo under time
    pressure: a confident, meaningless answer that looks like evidence.

    Splits. Write stratified train/validation/test manifests per class into `data/splits/`. Hold out
    a test split that is never seen during fine-tuning. Record the per-class counts.

    Reporting thresholds, which section 0 of the measurement document already commits to. A genus
    needs enough held-out test images for a ninety-five per cent top-3 claim (D-02) to mean
    anything; below roughly thirty test images the figure has no resolution and must be reported as
    insufficient-samples with its count rather than quoted as a percentage. This is the same
    discipline as RESEARCH.md's evaluation-harness example, which returns an explicit null for a
    zero-sample class rather than dropping it. Record which classes fall below the threshold — they
    are the classes that cannot enter the partial-go set (D-04) on this corpus, whatever the model
    does.

    Early-exit criterion, and it matters. If fewer than ten of the 34 classes reach a usable
    training count, stop here rather than spending the rest of the timebox fine-tuning against a
    corpus that cannot support a useful partial go. Record the coverage in section 9 of the
    measurement document, flag it clearly as an early no-go candidate, and raise it. A corpus that
    does not exist is a complete, well-evidenced answer to this phase's question, delivered in a day
    instead of three. It is not a failure of this plan.

    Gate file — this is what makes the early-exit criterion above an actual gate rather than an
    intention. Prose in a plan does not stop a downstream wave from executing; a file does. Write
    `spike/species-recognition/data/GATE` with exactly two lines, in both branches, always:

    - a first line reading `GATE-CORPUS: PASS` or `GATE-CORPUS: EARLY-NO-GO`, with nothing else on it
    - a second line reading `CLASSES-USABLE: <n>` giving the count of classes that reached a usable
      training count

    Plan 04 reads this file before spending anything on fine-tuning and refuses to start if the
    first line is not PASS. The file lives beside `data/splits/`, which plan 04 needs anyway, so it
    has exactly the same availability as the thing it gates — if the gate file is missing, the
    corpus is missing too, and plan 04 must treat a missing or unparseable gate file as a stop, not
    as a pass. Write the same token verbatim into section 9 of the measurement document and into
    this plan's SUMMARY, so the committed record and the machine-readable gate cannot drift apart.

    Measurement document, section 3. Record: every source used, with its licence, the URL or DOI it
    came from and the retrieval date; the licence filter applied and how many records it excluded;
    the species-to-genus aggregation rule and how many source species were discarded as
    out-of-list; a per-class table of train / validation / test counts covering all 34 classes,
    including the ones with zero images; and the list of classes below the reporting threshold.
    Reiterate that the corpus is single-subject only per D-10. Add a line recording, per RESEARCH.md
    assumption A4, that the CC-BY reading here is a documented reading of the licence text and not
    legal advice, and that it should be re-verified before the model actually ships in Phase 3.
