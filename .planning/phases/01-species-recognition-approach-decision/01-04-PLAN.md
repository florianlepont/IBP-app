<objective>
Fine-tune a mobile classifier on the corpus, export it to a quantised `.tflite`, and measure top-1
and top-3 accuracy per genus on the held-out test split — the first half of D-16's two-step
measurement.

Purpose: RESEARCH.md's second central finding is that no pretrained, licence-clean, CNPF-genus
classifier exists, so transfer learning onto an ImageNet-pretrained mobile backbone is the only
path. Its assumption A1 guesses low single-digit megabytes and tens of milliseconds and asks the
spike to verify rather than inherit that. This plan produces the model and the accuracy evidence;
plan 05 produces the latency and the field validation.

Output: an exported `.tflite` with a recorded on-disk size, a per-genus accuracy CSV, and sections
4 and 5 of the measurement document.

Timebox discipline (D-19): one candidate model measured properly beats two measured badly. Run the
second candidate only if the first finishes with time left. If the timebox expires mid-run, record
what was measured and stop — an incomplete measurement honestly reported is a legitimate input to a
no-go, not a reason to extend. A well-evidenced no-go is a successful outcome for this phase.
</objective>

  <action>
    Write the evaluation harness. This is RESEARCH.md's first Wave 0 gap and it produces the
    figures the whole phase turns on.

    Metric. Top-1 and top-3 accuracy, computed per class, following the shape RESEARCH.md's
    evaluation example gives: sort predictions descending, take the first k, and for each class
    compute the fraction of its test examples whose true label appears in that set. D-02 sets the
    bar at the correct genus within the top three, ninety-five per cent of the time.

    Per genus, never averaged (D-03). The output is one row per class. Do not compute, print, or
    write a single overall accuracy figure anywhere — D-03 exists because an average lets rare
    genera bury the fact that frequent genera work, and the partial-go rule in D-04 cannot be
    applied without the breakdown. If a weighted overall figure is genuinely useful as context, it
    belongs in prose with an explicit note that it is not the decision input, never as a headline
    number in the results table.

    Zero-sample and low-sample classes. A class with no test examples gets an explicit null in the
    results, following RESEARCH.md's example, which returns `None` rather than dropping the class.
    A class below the reporting threshold plan 02 set gets its raw hit count and sample count rather
    than a percentage, marked insufficient-samples. Both must appear as rows: all 34 classes are in
    the output, always. The temptation this guards against is a results table that shows twelve
    genera at ninety-eight per cent and reads like a go, while twenty-two classes quietly vanished.

    Statistical honesty. At the reporting threshold, ninety-five per cent leaves room for at most one
    or two misses, so a genus can cross or miss the bar on a single image. Record the raw hit count
    and sample count alongside every percentage so a reader can see how thin the evidence is, and
    note the resolution limit in section 5. This is what stops the ADR from treating a thirty-sample
    ninety-seven per cent as equivalent to a three-hundred-sample ninety-seven per cent.

    The partial-go column (D-04). Add a column marking, per class, whether it clears the D-02 bar.
    That column is the partial-go decision in raw form: the genera for which suggestions would be
    enabled, with manual entry kept for the rest. Include the classes that cannot be assessed at all
    — they do not clear the bar either, for a different reason, and the ADR has to say which reason
    applies to which genus.

    Confidence distribution, for D-12. The screen shows confidence in plain words — strong, medium,
    weak — not as a percentage. Those bands have to come from somewhere. Emit the distribution of
    top-1 confidence scores split by whether the prediction was correct, so plan 06 can propose
    thresholds that actually separate a reliable suggestion from a hesitant one rather than picking
    round numbers. Record the proposed cut points and what they cost in each direction.

    Also emit the top-3 candidate ordering for a sample of test images. D-11 puts the most likely
    genus first with the remaining candidates underneath, and it is worth knowing from the evidence
    whether the second and third candidates are usually plausible neighbours or noise — that is the
    difference between a useful candidate list and a decorative one.

    Outputs. Write `eval/results/per_genus_accuracy.csv` with one row per class: class name, test
    sample count, top-1 hits, top-1 accuracy, top-3 hits, top-3 accuracy, clears-bar flag, and a

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model zoo → spike host | ImageNet-pretrained weights are downloaded from a third-party host and executed as part of the training graph |
| training pipeline → decision | A defect in the label mapping or the export produces plausible numbers that misdirect the go/no-go |
| licence chain → shipped product | A permissive architecture built on restrictively-licensed weights or images is unshippable regardless of accuracy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Tampering | Pretrained backbone weights fetched at training time | medium | mitigate | Take weights only through the official `torchvision` / Keras applications API over HTTPS rather than an arbitrary download URL; record the weights identifier, source and licence in section 4 so the chain is auditable |
| T-01-11 | Tampering | Label-order mismatch between `genus_labels.txt`, the exported model's output layer and the results CSV | high | mitigate | Class order is read from `genus_labels.txt` in training, export and evaluation; task 1's gate asserts the model's output width equals the label count, and task 2's gate asserts every label appears as a results row |
| T-01-12 | Repudiation | Accuracy figures reported without the test-split size, date or source model, leaving them unreproducible | high | mitigate | Section 5 records test-split size, date and source model file; the CSV carries raw hit and sample counts beside every percentage |
| T-01-13 | Information Disclosure | The exported model memorises and can leak training images | low | accept | A 34-class quantised mobile classifier over public CC-BY/CC0 imagery carries negligible extraction risk, and the source images are already public under permissive terms |
</threat_model>
