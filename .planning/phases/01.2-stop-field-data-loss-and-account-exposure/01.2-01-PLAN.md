Fix audit finding A-C1 (lot L2): today the global `ThrottlerGuard` keys every request on `req.ip`, which behind Caddy is the proxy address, with a production limit of 10/min — one syncing device locks out every user. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Caddy → API | Client IP arrives only in X-Forwarded-For set by Caddy; the API trusts XFF only from the configured proxy range |
| Unauthenticated request → global throttler | The Authorization header is untrusted input at throttler time (not yet verified by AuthGuard) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.2-01 | Denial of Service | Global ThrottlerGuard keyed on proxy IP (A-C1) | mitigate | clientTracker keys on SHA-256(bearer) or trusted client IP; production default 600/min per client; E2E asserts independent buckets |
| T-01.2-02 | Spoofing | X-Forwarded-For forgery to get fresh buckets | mitigate | `trust proxy` = "loopback" (only the local proxy's XFF is honoured); Caddy overwrites client-supplied XFF by default; E2E asserts XFF honoured from loopback |
| T-01.2-03 | Denial of Service | Rotating fake bearer tokens to bypass per-token buckets | mitigate | second named throttler "ip" keyed on client IP with a 3000/min ceiling in production; E2E asserts the sixth rotated-token request is 429 |
| T-01.2-04 | Information Disclosure | Tracker keys stored in throttler memory | accept | SHA-256 hex of the token is stored in-process only, never logged or returned; not reversible to the token |
| T-01.2-05 | Denial of Service | Docker userland proxy makes every client appear as the bridge gateway, collapsing unauthenticated traffic into one bucket | mitigate | TRUST_PROXY env override documented (default "loopback" per D-05); manual post-deploy check in 01.2-VALIDATION.md; authenticated traffic is per-token regardless |
</threat_model>
