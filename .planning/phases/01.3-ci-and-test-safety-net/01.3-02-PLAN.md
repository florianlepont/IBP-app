<objective>
Two API-side infrastructure fixes that plan 05's CI jobs build on: (1) reset the E2E database before every run with a Jest `globalSetup` that drops the schema and re-runs migrations (D-08, audit T5), against a dedicated `_test` database that is never the dev database; (2) make the API image reproducible from the root lockfile, non-root and health-checked (D-04, audit CI-2, lot L6), with a root `.dockerignore` and the VPS README updated for the new in-image paths and a SHA-tag rollback.

Purpose: REQ-AUD-test-infra (E2E reset — Phase 01.4 relies on it) and REQ-AUD-reproducible-image. The CI wiring (context `.`, SHA tag, main-only push, the full ci.yml rewrite, which keeps the E2E database `ibp_test`) is plan 05; this plan only renames the current E2E job's database to `ibp_test` (Task 2).
Output: migrate.js export, e2e-env.js + global-setup.js + setup-e2e-env.js, api/.env.test.example, jest/npm script wiring, README/CLAUDE.md testing lines, rewritten Dockerfile, .dockerignore, VPS README update.

Safety model (checker blocker fix): D-08's reset is `DROP SCHEMA public CASCADE`. `api/.env.example` and `infra/docker-compose.yml` give local dev POSTGRES_HOST=localhost, POSTGRES_DB=ibp — the database `npm run dev:api:migrated` uses — so a host check alone would wipe the developer's data. The reset therefore refuses any database whose name does not end in `_test`, and the E2E scripts load a separate E2E env (`ibp_test`) before anything reads `api/.env`.

Sandbox note: no Docker daemon and no PostgreSQL here. Local proofs are static checks, a `pg`-stubbed run of globalSetup, and an npm-level simulation of the Dockerfile steps; the real `docker build`, container smoke run and two consecutive E2E runs are CI acceptance criteria checked in plan 06. So intermediate pushes keep the phase PR's E2E job green, Task 2 also makes a minimal edit to the current ci.yml `test-e2e-api` job (POSTGRES_DB ibp → ibp_test in the service and job env); no other wave-1 plan touches ci.yml, and plan 05's full rewrite (wave 2, depends on 02) keeps ibp_test.
</objective>
