| E2E runner → PostgreSQL | globalSetup issues DROP SCHEMA against whatever POSTGRES_* points at |

| GHCR image → VPS runtime | The VPS runs whatever :latest is, as the container user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.3-04 | Tampering | global-setup.js dropping a non-test database | mitigate | assertResettableDatabase refuses NODE_ENV=production and any host other than localhost/127.0.0.1/::1 unless E2E_ALLOW_REMOTE_DB_RESET=true; warn line names the target |
| T-01.3-05 | Information Disclosure | api/.env or other .env files entering the build context / builder layers | mitigate | .dockerignore excludes `**/.env` and `**/.env.*` (keeps only .env.example); runtime stage copies only dist, scripts, migrations |
| T-01.3-06 | Elevation of Privilege | Container running as root | mitigate | `USER node` in the runtime stage; CI image-check asserts `id -u` is not 0 |
| T-01.3-07 | Tampering | Dependency drift: image resolved versions without the root lockfile/overrides | mitigate | `npm ci --workspace api` against the copied root package-lock.json; `npm ls --omit=dev` checked in the simulation |
