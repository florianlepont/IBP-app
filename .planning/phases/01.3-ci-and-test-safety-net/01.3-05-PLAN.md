<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author (including forks) → workflow runner | Untrusted code runs in CI jobs with GITHUB_TOKEN |
| Third-party actions → runner | Action code executes with the job's token |
| CI → GHCR → VPS | Whatever lands on :latest is deployed within 5 minutes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.3-15 | Tampering | Re-tagged or compromised third-party action | mitigate | Every `uses:` pinned to a peeled commit SHA (acceptance grep); Dependabot github-actions keeps pins current |
| T-01.3-16 | Elevation of Privilege | Over-broad GITHUB_TOKEN | mitigate | Workflow permissions contents: read; pull-requests: read only on changes; packages: write only on build; security-events: write only on CodeQL analyze; persist-credentials false |
| T-01.3-17 | Elevation of Privilege | Non-main branch or dispatch pushing :latest to production (CI-2) | mitigate | build `if:` requires push event on refs/heads/main and runs after CI OK; workflow_dispatch removed; PRs only build with push: false |
| T-01.3-18 | Information Disclosure | Secrets exposed to fork PRs | mitigate | `pull_request` (never pull_request_target); only GITHUB_TOKEN used, only in build, which never runs on PRs; E2E values are non-secret CI constants |
| T-01.3-19 | Tampering | Half-pushed image when a newer main push cancels the build | mitigate | build concurrency group deploy-image with cancel-in-progress: false |
| T-01.3-20 | Tampering | Vulnerable dependency or malicious code merged | mitigate | npm audit --audit-level=high on all dependencies (D-01); CodeQL javascript-typescript on PRs + weekly |
| T-01.3-21 | Tampering | actionlint binary tampered in transit | mitigate | Release tarball verified with a pinned sha256 before execution |
| T-01.3-22 | Tampering | Cache poisoning of node_modules across branches | accept | GitHub scopes PR caches to the PR ref; main never restores PR-created caches; key is the lockfile hash |
</threat_model>
