<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile client -> API | Authenticated requests naming a survey id and attachment id |
| API -> object storage / local disk | The server reads stored bytes or signs a GET for them |
| client -> presigned URL | A bearer-less URL grants read access to one object for 5 minutes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.5-03 | Elevation of Privilege | download-url / content routes | mitigate | `getSurveyForUserOrThrow(this.db, surveyId, user.id)` runs before any attachment lookup; attachment lookup also filters `survey_id = $2 AND deleted_at IS NULL`; E2E case (2) proves another user gets 404 |
| T-01.5-04 | Information Disclosure | presigned GET URL | mitigate | 5-minute TTL, one object key, issued only to the owner; contract tells clients never to attach the bearer token to it (requires_auth false) |
| T-01.5-05 | Tampering / Information Disclosure | local content path | mitigate | `resolve(root, storage_key)` must start with `root + sep`, else 404 without reading (unit case with "../../etc/passwd") |
| T-01.5-06 | Spoofing | unauthenticated access | mitigate | Class-level AuthGuard; E2E case (5) asserts 401 |
| T-01.5-07 | Denial of Service | streaming large files | accept | Files are bounded by the existing 25 MB upload limit and the global per-client rate limit; mobile uploads are resized to <= 2048 px (plan 07) |
</threat_model>
