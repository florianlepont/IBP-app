One database per test file, so each seed scenario gets its own file.

expo-sqlite `withTransactionAsync` is not exclusive (other queries on the connection can interleave, C14); D-17 therefore adds a module-level mutex around every transactional writer.

Reentrancy design (why not a plain flag): React Native's Hermes has no AsyncLocalStorage, so at call time the helper cannot tell a nested call made from inside a running callback from an unrelated concurrent call made by another async flow; a global "callback running" flag would make the unrelated call throw, which is wrong. The helper is therefore made safe by an explicit handle: the callback receives a `TxHandle` (a distinct wrapper object, never the raw db), `runInTransaction(fn, tx)` with that live handle joins the open transaction (runs `fn(tx)` directly: no BEGIN, no mutex), and any code that may run inside a transaction takes a `DbExecutor` parameter. A forgotten handle can no longer hang the app silently: the mutex wait is bounded by `TRANSACTION_WAIT_TIMEOUT_MS` and then rejects with `Error("runInTransaction called reentrantly")` (the message names the only realistic cause; no transaction body does network I/O, so a legitimate wait is far below 30 s).
