<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored Auth0 credentials -> app UI | A cached profile is shown without a live /me call |
| device storage (local_meta) -> auth state | A value on disk decides which identity the UI displays |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.5-11 | Spoofing | cached profile after logout / account switch | mitigate | Cache is keyed by the id-token sub and only read for the same sub; clearSession (logout, session-ended, AUTH_REQUIRED) clears it; tests cover other-sub and logout |
| T-01.5-12 | Elevation of Privilege | writes while offline with a cached profile | mitigate | The cache only feeds display state; every write still needs a valid token through withAuthRetry and the phase 01.2 owner gate (syncAllowed default-deny) is unchanged |
| T-01.5-13 | Information Disclosure | profile JSON at rest | accept | Stored in local_meta beside the survey data it describes (same trust tier, RESEARCH V8); purged with it |
| T-01.5-14 | Denial of Service | refresh loop hammering /me | mitigate | Refresh only while profileFromCache is true, one in-flight call at a time, 60 s interval, stops after the first success |
</threat_model>
