Verified migration body (PATTERNS C-5, run on PG 16.13 inside one transaction): add nullable `seq BIGINT`; `UPDATE survey_events e SET seq = o.rn FROM (SELECT id, row_number() OVER (ORDER BY created_at, id) AS rn FROM survey_events) o WHERE o.id = e.id`; `ALTER COLUMN seq SET NOT NULL`; `ALTER COLUMN seq ADD GENERATED BY DEFAULT AS IDENTITY`; `SELECT setval(pg_get_serial_sequence('survey_events', 'seq'), COALESCE((SELECT MAX(seq) FROM survey_events), 0) + 1, false)`; `ADD COLUMN xid8 xid8 NOT NULL DEFAULT pg_current_xact_id()`; `CREATE UNIQUE INDEX idx_survey_events_xid8_seq ON survey_events (xid8, seq)`. Then synthetic events: `INSERT INTO survey_events (id, survey_id, actor_id, event_type, payload) SELECT gen_random_uuid()::text, s.id, NULL, 'backfilled', jsonb_build_object('reason', 'migration_014') FROM surveys s WHERE s.user_id IS NOT NULL AND NOT EXISTS (SELECT 1 FROM survey_events e WHERE e.survey_id = s.id)`.

pg driver types (PATTERNS C-11, verified): `bigint` and `xid8` come back as JS strings; binding strings with `$1::xid8` / `$2::bigint` works. Never `Number()` an xid8.

Current cursor helpers (api/src/surveys/surveys-normalize.utils.ts ~399-426): `parseChangesCursor(cursor?)` returns `{ timestamp, eventId, original }`, throws `new BadRequestException("Invalid sync cursor")` when the part before `|` does not `Date.parse`; `buildChangesCursor(timestamp, eventId)` returns `${timestamp}|${eventId}`. Legacy cursors in installed apps look like `2026-03-09 10:20:31.991+00|8ac...` (created_at::text), and some carry a SURVEY id instead of an event id (PATTERNS C-6).
