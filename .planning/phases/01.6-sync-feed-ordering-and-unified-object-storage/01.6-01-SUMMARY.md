# Phase 01.6 Plan 01: survey_events seq/xid8 migration and v2 cursor helpers Summary

**Migration 014 adds `survey_events.seq` (identity, backfilled in `(created_at, id)` order) and `survey_events.xid8` (default `pg_current_xact_id()`) with a unique `(xid8, seq)` index, and inserts one synthetic `backfilled` event per owned event-less survey. A scratch-schema E2E spec proves this on seeded rows. New `parseSyncChangesCursor`/`buildSyncChangesCursor` helpers handle `v2:<xid8>:<seq>` and legacy `<timestamp>|<id>` cursors as strings.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The legacy cursor check copied from parseChangesCursor accepted "seq:5"**
- **Found during:** Task 2 (GREEN)
- **Issue:** The plan said the legacy parse should be identical to `parseChangesCursor` (`Date.parse` on the part before `|`). V8's lenient `Date.parse("seq:5")` returns a valid date, so the required reject case `"seq:5"` passed validation.
- **Fix:** A legacy cursor must now contain `|` and its timestamp must start with `YYYY-MM-DD` followed by a space or `T`, besides passing `Date.parse`. Any `v2:`-prefixed cursor that fails the strict regex is rejected before the legacy branch. Every legacy cursor ever emitted came from `buildChangesCursor` as `${timestamptz}|${id}` (both known shapes are in the spec), so installed apps are unaffected.
- **Files modified:** api/src/surveys/surveys-normalize.utils.ts, api/test/surveys-normalize.utils.spec.ts
- **Commit:** 71ad849
