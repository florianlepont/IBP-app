Rewrite targets (RESEARCH Pattern 6 table, verified on PG16 at 10k: map items 23.6 → 5.0 ms, bbox status 1.6 ms, no seq scan):
- map items: a subquery `SELECT … FROM surveys s WHERE s.status = 'submitted' AND s.visibility = 'public' AND s.deleted_at IS NULL [same optional filters as today] ORDER BY s.submitted_at DESC LIMIT 500` (the partial index predicate must match literally), then `LEFT JOIN LATERAL (SELECT … FROM survey_parcels sp JOIN parcels p ON p.parcel_id = sp.parcel_id WHERE sp.survey_id = s.id) agg ON true` producing exactly the aggregates today's GROUP BY produced, same final ORDER BY.
- parcel status DB path: `FROM parcels p WHERE p.centroid_lat BETWEEN $minLat AND $maxLat AND p.centroid_lng BETWEEN $minLng AND $maxLng` + `JOIN LATERAL (SELECT … FROM survey_parcels sp JOIN surveys s ON s.id = sp.survey_id WHERE sp.parcel_id = p.parcel_id AND s.status = 'submitted' AND s.visibility = 'public' AND s.deleted_at IS NULL AND <year filter> ORDER BY s.observation_year DESC NULLS LAST, s.version_number DESC NULLS LAST, s.submitted_at DESC NULLS LAST LIMIT 1) latest ON true`, same LIMIT 1000 and output columns as today. Note: rows whose centroid is non-numeric now get NULL generated columns and are simply outside every bbox (today they would raise a cast error).
- IGN path studied query (from plan 09): same LATERAL "latest public per parcel" form, restricted with `p.commune_code = ANY($n::text[])`.
public-map.queries.ts contract: `export const PUBLIC_MAP_ITEMS_SQL`, `export const PUBLIC_PARCEL_STATUSES_BBOX_SQL`, `export const PUBLIC_STUDIED_BY_COMMUNES_SQL` (parameterised text; if today's optional filters make the SQL dynamic, export a pure builder `buildPublicMapItemsQuery(filters): { text: string; values: unknown[] }` instead, and use it in the service, the spec and the script).
EXPLAIN seed (RESEARCH Code Example 5): 200 users, 8 000 parcels with random centroids in France, 10 000 surveys (40 % submitted, 20 % public, so ~2 000 public submitted), 1-3 links per survey, all inside `BEGIN … ROLLBACK` on one client; `ANALYZE` is allowed in the transaction and is rolled back. Specs run --runInBand, so the long transaction does not stall other specs' feed (RESEARCH Pitfall 11).
