From plan 02 (api/src/surveys/list-cursor.ts): `encodeListCursor({ t, i }): string` ("v1:" + base64url JSON); `decodeListCursor(raw, { idPattern? }): { t; i } | null` (400 "Invalid cursor"); `parseListLimit(raw): number | null` (400 "Invalid limit", 1..100). `t` is always the PostgreSQL `::text` of the timestamp (microsecond precision preserved), validated by isStrictTimestamp.
Consumers (RESEARCH Pattern 5): the mobile app calls only `GET /surveys/:id/events` without parameters and reads only `items`; it never calls GET /surveys or GET /reports. GET /surveys already answers `{ items, next_cursor: null }`.
Per-endpoint keyset (existing indexes cover all three: idx_surveys_user_updated (user_id, updated_at DESC), idx_survey_events_survey (survey_id, created_at DESC), idx_reports_status_created):
- GET /surveys (SurveysService.listForUser, today `SELECT id, site_name, status, visibility, parcel_id, observation_year, version_number, updated_at::text, sync_version FROM surveys WHERE user_id = $1 AND deleted_at IS NULL [status/from/to/q filters] ORDER BY updated_at DESC`): order becomes `updated_at DESC, id DESC`; keyset `(updated_at, id) < ($n::timestamptz, $m)` appended as the last filter; cursor { t: updated_at text, i: id }. Move the SQL into `SurveysRepository.buildListForUserQuery(userId, filters, page: { limit: number | null; after: ListCursor | null }): { text; values }` (pure, exported) plus `listForUser(db, …)`.
- GET /surveys/:id/events (SurveyEventsService.listForSurvey from plan 08): order `created_at DESC, seq DESC`; keyset `(created_at, seq) < ($n::timestamptz, $m::bigint)`; cursor { t: created_at text, i: seq::text } decoded with idPattern `/^\d{1,19}$/`; select `seq::text` for the cursor but strip it from each returned item so the item shape is unchanged; response becomes `{ items, next_cursor }` (additive key). Export `buildEventListQuery(surveyId, page)`.
- GET /reports (ReportsService.listReports): order already `created_at DESC, id DESC`; keyset `(created_at, id) < ($n::timestamptz, $m::uuid)`; cursor { t: created_at text, i: id } decoded with a UUID idPattern; response `{ items, next_cursor }`. Export `buildReportListQuery(status, page)`.
Paging rule: limit null → no LIMIT, next_cursor null (identical rows to today). limit n → fetch n + 1; if n + 1 rows came back, drop the extra and set next_cursor from the n-th row; otherwise next_cursor null. A cursor without a limit is accepted and applies the keyset with no LIMIT.
Controllers (pattern map C-4): keep individual `@Query("status")` etc. and add `@Query("limit") limit?: string`, `@Query("cursor") cursor?: string`; parse with parseListLimit/decodeListCursor in the controller or service; never introduce a class DTO (forbidNonWhitelisted would turn today's unknown parameters into 400s). The events route keeps SafeIdPipe on :id.
