## PR #159 body draft

The orchestrator uses this text for the PR description.

---

### Phase 01.9: mobile state, French text, accessibility and hygiene

**What changes for users**

- **Faster app.** Status updates, typing in a survey and list refreshes no longer re-render every tab. The state is split into five memoised contexts, and the survey list is a virtualised list with memoised rows. It stays fluid with 500 surveys and no longer parses every survey when it loads.
- **French everywhere.** All text comes from one French catalogue. Status messages no longer show ids or technical errors, the iOS permission prompts are in French, and the "Debug" tab only shows in development builds.
- **Accessible buttons.** Buttons in the survey detail, survey form and map screens have a French VoiceOver/TalkBack label and a role.
- **4 tabs.** Accueil, Mes Relevés, Explorer, Compte. Search is now in the header of Mes Relevés, and the iPhone Release build always uses the native "liquid glass" bar.
- **Map by area.** Explorer loads only the visible area, about 0.4 s after the map stops moving, groups nearby surveys into clusters, and no longer re-centres itself in a loop.
- **Fixes.** The draft card's progress bar now reads the completion correctly, and a report's confirmation on the map now shows.

**What changes for the owner**

- The API no longer sends email. Leftover `SMTP_*` lines in the VPS env file do not block the deploy; `check-env.sh` reports them as INFO ("obsolete"). You can delete them when convenient.
- CI now builds Android and iOS natively (unsigned) on every mobile change.
- One device check after the deploy (below). Nothing else to do by hand.

**Compatibility**

- Map API: `GET /v1/public/map-items` accepts an optional `bbox`. Without it the response is unchanged, so installed apps keep working.
- Phone database: SQLite migration 2 only adds a column, filled when surveys are written. Existing surveys stay.
- Dependencies: unused packages removed (root Expo leftovers, bcryptjs, @nestjs/schedule, nodemailer); supercluster 9.1.0 added. The set of native modules is unchanged (29).

**Render counts (committed test harness, 20 surveys)**

| Scenario | Before | After |

| Status update | 27 renders | 1 |
| Keystroke in the form | 27 | 3 |
| Keystroke + autosave | 56 | 8 |
| One survey refreshed | 28 | 5 |

**Device check after the deploy (owner, in French)**

Contrôle sur l'iPhone, après la mise en production (6 étapes, environ 15 minutes) :

1. Sur le Mac, dans le dossier cortege : `git checkout main && git pull && npm install`
2. Lancer `grep NATIVE_TABS mobile/.env` : si une ligne `EXPO_PUBLIC_ENABLE_NATIVE_TABS=false` s'affiche, la supprimer du fichier.
3. Brancher l'iPhone, puis : `cd mobile && npx expo run:ios --device --configuration Release`
4. Se connecter. En bas, la barre « verre liquide » montre 4 onglets : Accueil, Mes Relevés, Explorer, Compte. Toucher chaque onglet : chacun s'ouvre, et la carte d'Explorer affiche des relevés.
5. Dans Mes Relevés, toucher la recherche en haut et taper le nom d'un relevé : la liste se filtre.
6. Mettre l'iPhone en mode avion, fermer complètement l'app (glisser vers le haut), la rouvrir : vos relevés sont toujours là.

Si tout est bon, répondre « approuvé ». Sinon, indiquer le numéro de l'étape qui ne va pas et ce que vous voyez.
