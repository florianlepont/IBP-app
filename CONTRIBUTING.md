# Contributing

Short version: **this repository is readable, not reusable, and it does not
accept code contributions.** That is unusual for a public repository, so here
is why, and what you can do instead.

## Why the code is public

For transparency, for review, and so the work is visible. It is published under
a source-available licence — see [LICENSE](LICENSE). The code may be read; it
may not be reused, copied or adapted without written permission. Parts of it
are not the maintainer's to license at all: the brand assets belong to the
association Etats Sauvages, and the IBP methodology to CNPF and INRAE Dynafor
(see [NOTICE.md](NOTICE.md)).

## Pull requests

Pull requests are not accepted, and open ones will be closed. This is not about
the quality of the contribution: the project has a single maintainer, and a
licence that makes the status of contributed code ambiguous.

The exception is a fix you were explicitly asked for.

## What is welcome

**Bug reports.** If you use the app and something is broken, open an issue with
what you did, what you expected, and what happened.

**Security reports.** Privately, never in an issue — see
[SECURITY.md](SECURITY.md).

**Questions about the IBP methodology** belong with CNPF, not here. This
project implements the method, it does not define it:
<https://www.cnpf.fr/ibp>.

## About the open issues

The issue tracker carries the full product backlog as user stories. They are
planning artefacts, not calls for help. An issue being open does not mean it is
available to work on.
